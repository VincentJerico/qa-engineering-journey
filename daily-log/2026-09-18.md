## What I learned
- "Works" ≠ "correct": asserting the *specific* status code is how API design issues surface.
- Web-first assertions (`toHaveCount`, `toBeVisible`) remove timing flakiness that one-shot reads cause.
- `test.fail()` is a clean way to keep a known bug tracked in a green suite until it's fixed.
- GitHub Actions deprecations are about the *action version's* Node runtime, not the `node-version` input.
